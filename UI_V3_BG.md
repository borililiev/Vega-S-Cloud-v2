# Vega-S Cloud v3 — нов потребителски интерфейс (16.11.2026)

Тази промяна засяга **само сървъра** — FastAPI, CSS, HTML и JavaScript. Не е необходимо да препрограмираш работещия Sonoff TH или да променяш Caddy, рутера и съществуващите TLS сертификати.

## Какво се променя

- **Термостат**: начална страница в тъмния стил на локалния интерфейс v6.x; голяма текуща температура, зададена температура с +/− 0,5 °C, червен индикатор за релето, един голям бутон Включи/Изключи, статус Онлайн/Офлайн и избор на устройство.
- **Енергия**: изчислени kWh и часове работа за днес и текущия месец, разделяне на дневна/нощна енергия, очакван разход в EUR след настройка на тарифи и графики за 24 ч./месец/година.
- **Админ / Настройки**: добавяне на термостат към **избран активен потребител** с ID и код; добавяне/деактивиране на потребители, тарифи за всяко устройство, локации, OTA и журнал.
- **Профил**: смяна на личната парола, достъпна на всеки потребител.

## Важно за показателите на енергията

Сегашният ESP8266/Sonoff v6.6 изпраща в облака текущите стойности **relay** и **power_w**, но **НЕ** изпраща локалните таблици HeaterStats. Сървърът сега записва очаквана консумация като време с включено реле × номинални ватове. Това **не е измерване с електромер**. Не се отчитат периода преди обновяването или периоди с пропусната облачна връзка (прекъсвания над 40 s); сървърът не гадае дали е имало отопление през прекъсването. Възможни са малки отклонения при смяна на релето между два синхронизиращи отчета.

При зададени две положителни тарифи в админ панела се показва прогноза за цена. Ако цените са нула/не са настроени, стойността е „—“. Промените на тарифите преизчисляват прогнозната цена на историческите kWh. Данните се показват по часовата зона **Europe/Sofia**. Ако са необходими точните стойности от локалната памет на устройството, ще трябва отделно да добавим синхронизация на HeaterStats към фърмуера.

## Безопасна инсталация на работещия Ubuntu Docker сървър

**Не изпълнявай docker compose down -v. Не изтривай .env, volume-ите и Caddy сертификатите.**

```bash
cd /opt/Vega-S-Cloud-v2

# 1. Архивирай старите изходни файлове
BACKUP="$HOME/vega-cloud-ui-before-v3-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BACKUP"
cp -a app requirements.txt "$BACKUP"/
echo "Source backup: $BACKUP"

# 2. Направи онлайн backup на SQLite в постоянния Docker volume
docker compose exec -T cloud python - <<'PY'
import datetime, os, sqlite3
src = os.getenv('VEGA_DB', '/data/vega.sqlite3')
dst = '/data/vega-backup-before-ui-v3-' + datetime.datetime.now(datetime.timezone.utc).strftime('%Y%m%d-%H%M%S') + '.sqlite3'
with sqlite3.connect(src) as source, sqlite3.connect(dst) as backup:
    source.backup(backup)
print('SQLite backup:', dst)
PY

# 3. Обнови само сървърния код от GitHub
git status --short
git pull --ff-only

# 4. Пресъздай само Python приложението; Caddy остава работещ
docker compose up -d --build --no-deps cloud
docker compose ps
docker compose logs --tail=60 cloud

# 5. Проверка на вътрешния API
docker compose exec -T cloud python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8000/health',timeout=5).read().decode())"
```

Очакваният резултат е `{"ok":true,"service":"vega-cloud-v2"}`; името на health услугата не е променяно. Отвори познатия публичен адрес и направи твърдо обновяване на браузъра (Ctrl/⌘ + Shift + R).

Ако `git pull --ff-only` откаже заради локално променен `Caddyfile`, **не изтривай локалните промени с git reset**; запази и прегледай конфликта, преди да продължиш.

## Проверки

```bash
python3 -m pip install -r requirements.txt pytest httpx
python3 -m pytest tests -q
```

Провери с администратор: таб „Админ / Настройки“, избор на собственик, тарифи, съществуващи потребители, устройства. С обикновен потребител трябва да виждаш само собствените устройства и „Профил“, не администраторските функции.

## Връщане към стария изглед

Използвай архивираната папка `$BACKUP` (виж първата стъпка). Старият backend игнорира добавените SQLite таблици; **не е нужно да изтриваш новите данни**. След връщане на файловете изпълни `docker compose up -d --build --no-deps cloud`.

Обратната съвместимост на локалния ESP протокол е запазена — `/device/enroll` и `/device/{id}/sync` не изискват нови полета.
