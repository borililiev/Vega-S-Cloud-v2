# Vega-S Cloud — административен списък и собственост на термостатите

## Нови функции

В таб **„Админ / Настройки“** има отделна секция **„Всички термостати“** с общ брой, текущ собственик, онлайн статус, версия, тарифи и контроли:

- **Смени собственик**: избери друг активен потребител от падащото меню и потвърди. Не се изисква повторно сдвояване или обновяване на фърмуера. Старият потребител губи достъп на ниво сървър; новият вижда термостата при следващото обновяване.
- **Премахни от профила**: освобождава термостата, но **не го изтрива от сървъра**. Историята на енергията се запазва. За ново добавяне с ID и код натисни **„Смени кода за добавяне“** от локалната страница `/cloud` на термостата.
- Контролите са достъпни само за администратор. Неактивни профили не могат да бъдат избрани за нов собственик.

При смяна на собственик и при премахване се изчистват запазените координати и се отменят **чакащите** команди и OTA задачи. Команди, които са вече получени и изпълнени от устройството, не могат да се върнат назад; локалните хардуерни защити продължават да работят независимо от облака.

След освобождаване старият код за сдвояване се обезсилва на сървъра, за да не може предишният собственик да добави обратно устройството само със стария код. Облачният токен на самия термостат остава валиден и телеметрията продължава да работи.

## API

- `GET /api/admin/devices` — списък на всички устройства, включително без собственик. Не връща ключове или кодове.
- `PUT /api/admin/devices/{id}/owner` с `{"owner_id": 123}` — прехвърля собствеността към активен потребител.
- Същият `PUT` с `{"owner_id": null}` — премахва устройството от профила.
- Старият `POST /api/admin/devices/{id}/release` продължава да работи със същото поведение.

Всички административни заявки изискват активна администраторска сесия, валидна проверка на Origin и CSRF токен.

## Обновяване на работещия Docker сървър

**Не променяй Caddy, фърмуера на термостата или Docker volumes. Не използвай `docker compose down -v`.**

```bash
cd /opt/Vega-S-Cloud-v2

# Резервно копие на изходните файлове
BACKUP="$HOME/vega-before-owners-v4-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BACKUP"
cp -a app requirements.txt "$BACKUP"/

# Онлайн backup на SQLite в постоянния volume
docker compose exec -T cloud python - <<'PY'
import datetime,os,sqlite3
src=os.getenv('VEGA_DB','/data/vega.sqlite3')
dst='/data/vega-before-owners-v4-'+datetime.datetime.now(datetime.timezone.utc).strftime('%Y%m%d-%H%M%S')+'.sqlite3'
with sqlite3.connect(src) as db, sqlite3.connect(dst) as out:
    db.backup(out)
print('Database backup:',dst)
PY

git status --short
git pull --ff-only
docker compose up -d --build --no-deps cloud
docker compose ps
docker compose logs --tail=40 cloud
```

Ако `git pull` откаже заради локални промени, **спри и прегледай конфликта**, без `git reset --hard`.

Отвори `https://213.91.182.27:38443`, направи **Ctrl/Cmd + Shift + R** и влез като администратор. Термостатът не се препрограмира. През потребителските профили провери, че всяко устройство се вижда само от текущия си собственик.
